What to focus on

19 study days, then the interview. Arrays and hash maps are already comfortable, so the time goes to graphs, trees, search, heaps, backtracking and DP. The goal is not a problem count. It is this: see an unfamiliar prompt, name the structure underneath it, state a baseline, derive something better, write clean Python, and test it out loud.

The one habit worth drilling every dayBefore you write a line, finish one sentence — “dfs(node) returns…”, “the window always contains…”, “lo is the smallest value that could still be the answer”. Google is scoring the reasoning. A stated invariant is the cheapest possible evidence of it.

Where the hours go

Tier 1~half your time

Graphs and trees. Grid and adjacency traversal, BFS by levels, topological sort, Dijkstra. Tree recursion, level order, BST bounds, lowest common ancestor.

This is the bulk of what Google actually asks, and it is where your prep gap is. Everything in tier 2 shows up wrapped in one of these.

Tier 2~a third

Binary search on an answer, heaps and top-K, intervals and greedy, backtracking with pruning.

High frequency, small surface area. Each is one template plus one invariant you have to say out loud.

Tier 3the rest

DP and Union Find — recognise and implement the common shapes only. Take-vs-skip, prefix feasibility, two-sequence DP. Union Find for “edges arrive one at a time”.

Worth being unsurprised by. Not worth becoming a specialist in with 19 days on the clock.

Skipdeliberately

Minimum spanning trees, tries beyond the basics, segment trees, KMP and friends, bit tricks, Hard DP.

Low probability at L4, and every hour here is an hour not spent on tier 1. If one appears, modelling the problem clearly will earn more than a half-remembered algorithm.

The other half of the score

  • Narration. Clarify, baseline, invariant, code, walk through, complexity, follow-up — in that order, every time. An unspoken correct approach scores below a spoken one.
  • Follow-ups. Google interviewers change the question. After every solved problem, answer one out loud: what if the weights weren’t equal? what if the input didn’t fit in memory? what if duplicates were allowed? what if the tree had cycles? Two minutes, every problem. This is the L4 differentiator and it costs almost nothing.
  • Recovery. Being wrong and catching it yourself reads as strength. Practise saying “that duplicates queue entries — I should mark seen on enqueue instead” rather than silently editing.
Not covered hereThis plan is coding rounds only. The loop also has a Googleyness / behavioural round, and it is scored. Three 30-minute slots are built into the schedule below (Aug 25, Aug 31, Sep 6) for STAR stories — conflict, failure, ambiguity, influence without authority, a project you owned end to end. Write them once, out loud, and stop. Do not let this become a fourth thing to cram.

The 19 days

Two problems are mandatory; the third is a transfer test and it is always the one you drop when time runs out. Every day has one measurable finish line — if you can’t do the done when, the day isn’t finished, and the next day loses its third problem instead.

Re-solve ruleAnything that needed a hint or an editorial goes back on the next day’s list, from a blank file. Backlog beats new topics, always.

def first_true(lo, hi, feasible):
    # lo = smallest value that could still be the answer
    # hi = smallest value known to be feasible
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid          # mid might be the answer, so keep it
        else:
            lo = mid + 1      # mid is ruled out
    return lo

Union Find + catch-up

Study firstfind and union, with path compression
python
parent = list(range(n))
rank = [0] * n

def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])   # path compression
    return parent[x]

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False                  # already connected -> this edge is a cycle
    if rank[ra] < rank[rb]:
        ra, rb = rb, ra
    parent[rb] = ra
    if rank[ra] == rank[rb]:
        rank[ra] += 1
    return True

How a day runs

The study block — about 100 minutes

  • 10 min — templates from memory. Blank file, no reference. Two of: DFS, BFS with deque, heapq push/pop, binary search boundary, Kahn, Dijkstra, backtracking skeleton. Rotate so each is typed roughly every third day.
  • 45 min — the first mandatory problem, derived rather than recalled. About 30 minutes of genuine attempt on a new Medium before reading anything, and then only enough to find the missing idea.
  • 30 min — the second mandatory problem.
  • 10 min — follow-up and error log. One changed-constraint question answered out loud, and one line in the log for anything that went wrong.
  • The third problem is a bonus, not a debt. Backlog and re-solves outrank it every time.
Timer disciplineNew Medium: 30 minutes of real attempt before a hint. Timed round: 45 minutes, hard stop. Anything you needed help with goes on tomorrow’s list.

What narration sounds like

  • Clarify — “Can there be duplicates, and may I modify the input?”
  • Baseline — “Every pair is O(n²). The repeated scan is the waste; a hash map removes it.”
  • Define state — “dfs(node) is the maximum depth of the subtree rooted at node.”
  • Invariant — “The window always holds at most k characters beyond its most frequent one.”
  • Self-correct — “That duplicates queue entries. I’ll mark seen on enqueue instead.”
  • Complexity — “Each node and edge once, so O(V+E) time, O(V) for the queue and visited set.”
  • Follow-up — “With unequal weights BFS stops being valid; I’d move to Dijkstra for non-negative edges.”

What changed from the first draft of the plan
  • Timed rehearsal moved to day 3 (Aug 22) instead of day 15. Two weeks of untimed solving followed by a sudden mock is how time management becomes the thing that fails.
  • Word Ladder demoted to a modelling exercise. It is a Hard whose lesson — the graph is hidden inside the story — takes ten minutes to absorb and two hours to grind out. 1091 takes the coding slot instead.
  • Open the Lock moved to Aug 29 as the first unseen timed problem, which frees repair day to actually repair rather than teach.
  • MST/Prim made optional and Sep 1 turned into a catch-up day. Nineteen straight days with no slack is a plan that breaks on the first bad evening.
  • Linked lists added back via 143 on Sep 2. They were cut entirely from the original plan, and they are the one area with a documented history of silent bugs — see the checklist.
  • Daily template warm-up and follow-up drill added. Fifteen minutes a day, spaced, aimed straight at retrieval speed and the follow-up questions.
  • Behavioural prep scheduled in three 30-minute slots. It was missing from a plan for a loop that scores it.
  • Every day got a measurable finish line, and the third problem was made explicitly droppable so the backlog can never lose to new material.
