Part one — core patterns

[0]Two pointers, converging

TriggerSorted array and you want a pair. Or you’re checking symmetry.

The move

One pointer at each end, moving inward. Each comparison discards a candidate, so you finish in one pass instead of checking every pair. O(n) time, O(1) space.

Template — Valid Palindrome (125)

python
def isPalindrome(self, s):
    left, right = 0, len(s) - 1

    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1

        if s[left].lower() != s[right].lower():
            return False

        left += 1
        right -= 1

    return True

isalnum() means “is alphanumeric” — true for letters and digits, false for punctuation and whitespace. So not s[left].isalnum() reads as “this is a character to skip”.

Watch forThe skip loops need left < right in their conditions, or a punctuation-only string walks a pointer off the end.

[1]Two pointers, read / write

Trigger“In place”, “return k”, “no extra space” — removing or reordering elements.

The move

A read pointer scans everything; a write pointer trails behind marking where the next kept value goes. Because write never passes read, you never overwrite a value you still need.

Template — Move Zeroes (283)

python
def moveZeroes(self, nums):
    write = 0

    for read in range(len(nums)):
        if nums[read] != 0:
            nums[write] = nums[read]
            write += 1

    while write < len(nums):
        nums[write] = 0
        write += 1

Remove Duplicates (26) and Remove Element (27) use the identical structure and return write. Merge Sorted Array (88) runs it backwards so you fill the padding without clobbering unread values.

Watch fornums = something rebinds a local name and does nothing to the caller’s list. In place means nums[i] = x or nums[:k] = other.

Harder variant — Remove Duplicates II (80)

Same shape, but each value may appear up to twice instead of once. The write condition changes from “different from the last kept value” to “different from the value two slots back” — compare nums[read] against nums[write - 2] rather than against a separately tracked previous value.

python
def removeDuplicates(self, nums):
    write = 2                        # first two elements are always kept

    for read in range(2, len(nums)):
        if nums[read] != nums[write - 2]:   # would this break the "at most twice" rule?
            nums[write] = nums[read]
            write += 1

    return write

Comparing two slots back rather than one is the whole trick: it lets a value repeat once (nums[write - 1] may equal nums[read]) but blocks a third occurrence (nums[write - 2] may not).

[2]Sliding window

Trigger“Contiguous subarray” or “substring” plus a constraint — longest, shortest, at most k.

The move

Expand right; when the constraint breaks, shrink from the left. Both pointers only move forward, which is what makes it O(n) rather than the O(n²) of checking every subarray.

Template — Longest Substring Without Repeating (3)

python
def lengthOfLongestSubstring(self, s):
    seen = set()
    left = 0
    best = 0

    for right in range(len(s)):
        while s[right] in seen:
            seen.remove(s[left])
            left += 1

        seen.add(s[right])
        best = max(best, right - left + 1)

    return best
Watch forWindow length is right - left + 1 — both ends are inside the window.

Fixed-size variant

When the window never changes size — substring search, for instance — there is no shrinking. Just slide: for i in range(n - m + 1).

[3]Hash map

Trigger“Have I seen this”, “does a match exist”, counting, duplicates. If you’re writing a nested loop to search for a value, use this instead.

The move

Trade space for time. Dict and set operations are O(1) average, so replacing a nested scan turns O(n²) into O(n) at the cost of O(n) space. That trade is the whole point, and it’s the thing to say out loud in an interview.

Template — Two Sum (1)

python
def twoSum(self, nums, target):
    seen = {}

    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i

    return []
Watch forCheck for the complement before inserting the current number, or a value can pair with itself.

The three things a hash map is for

Almost every hash problem is one of these. Naming which one you’re in tells you what the values should be.

One — membership

“Have I seen this?” Use a set. No values needed.

python
seen = set()
for x in nums:
    if x in seen:
        return True
    seen.add(x)

Two — counting

“How many of each?” Values are numbers.

python
counts = {}
for c in s:
    counts[c] = counts.get(c, 0) + 1

Three — grouping

“Which things share a property?” Keys are the property, values are lists.

python
groups = defaultdict(list)
for word in strs:
    groups[fingerprint(word)].append(word)
return list(groups.values())

A fourth, less common: remembering where something was, with indices as values. That’s Two Sum.

Hashable keys, and the fingerprint trick

Keys must be hashable

Dict keys and set members must be immutable. This is the constraint that silently blocks the obvious approach.

python
"aet"            # string  - fine
(1, 0, 2)        # tuple   - fine
frozenset(x)     # fine
["a","e","t"]    # list    - TypeError
{"a": 1}         # dict    - TypeError

So a letter-count fingerprint can’t be a dict — convert it to a tuple. Grid coordinates work as seen[(r, c)] but not seen[[r, c]].

Grouping by a computed key

The move behind Group Anagrams: when you need things that share a property grouped together, make the property the key. No comparison between items ever happens.

python
from collections import defaultdict

def groupAnagrams(self, strs):
    groups = defaultdict(list)

    for word in strs:
        key = "".join(sorted(word))     # anagrams share a sorted form
        groups[key].append(word)

    return list(groups.values())

The alternative fingerprint is a 26-slot frequency tuple — tuple(counts), using ord(ch) - ord("a") as the index. Both convert an unhashable fingerprint into a hashable one. Sorting is O(k log k) per word and shorter to write; counting is O(k) and the better answer if an interviewer pushes. Same move solves Group Shifted Strings (249) and Find Duplicate File in System (609).

Two-way mapping — Isomorphic Strings, Word Pattern

Isomorphic Strings (205) and Word Pattern (290) need consistency in both directions. One dict only enforces one direction — a → dog and b → dog both pass individually, but two letters can’t claim the same word.

python
if val not in mapping:
    if word in used:
        return False
    mapping[val] = word
    used.add(word)
elif mapping[val] != word:
    return False

The alternative is converting both sides to a canonical shape and comparing them.

python
def shape(seq):
    seen = {}
    out = []
    for item in seq:
        if item not in seen:
            seen[item] = len(seen)      # first distinct -> 0, second -> 1
        out.append(seen[item])
    return out

return shape(pattern) == shape(words)

"abba" and ["dog","cat","cat","dog"] both become [0,1,1,0].

Seven mistakes to check for

Rebinding instead of assigning into

The most common one by far. Same error as nums = result instead of nums[:k] = result.

python
storage = {letter: 1}        # replaces the WHOLE dict
storage[letter] = 1          # sets one key - what you meant

Reading a key to test whether it exists

python
if storage[key] not in storage:    # KeyError on the first pass
if key not in storage:             # correct

get() without a default

Returns None, and None != 0 is true — so the check you meant to fail quietly passes.

python
storage.get(letter)          # None if absent
storage.get(letter, 0)       # 0 if absent - almost always what you want

get() when the value can be falsy

A key holding 0 looks identical to a missing key. Use in when existence itself is the question.

python
storage = {"a": 0}
if storage.get("a"):      # False - but the key exists
if "a" in storage:        # True  - correct

Treating the returned value as an object

storage.get(k) returns the value itself. There is no .value on it.

append returns None

python
storage[k] = storage[k].append(x)    # sets the value to None
storage[k].append(x)                 # correct - no assignment

Appending to a key that doesn’t exist yet

python
storage.setdefault(k, []).append(x)   # creates the list if missing
groups = defaultdict(list)            # or avoid it entirely
Counter and defaultdict shortcuts
python
from collections import Counter, defaultdict

Counter(s)                   # {item: count} in one call
Counter(s).most_common(1)    # [(most frequent, its count)]
Counter(a) - Counter(b)      # subtract counts, drops zero and below
Counter(a) == Counter(b)     # anagram check in one line

defaultdict(list)            # missing key -> []
defaultdict(int)             # missing key -> 0, so counts[k] += 1 just works

Counter(a) - Counter(b) being empty means b covers a — that’s Ransom Note (383) in one line.

[4]Prefix sum

TriggerRepeated range queries, or “how many subarrays sum to k”.

The move

Keep a running total. A subarray ending here sums to k exactly when some earlier prefix equals running - k, so a hash map of prefixes seen so far answers the question in one pass.

Template — Subarray Sum Equals K (560)

python
def subarraySum(self, nums, k):
    counts = {0: 1}
    running = 0
    total = 0

    for num in nums:
        running += num
        if running - k in counts:
            total += counts[running - k]
        counts[running] = counts.get(running, 0) + 1

    return total

The {0: 1} seed covers subarrays starting at index 0.

Why not sliding windowNegative numbers break monotonicity — growing the window can shrink the sum. Sliding window needs that property; prefix sum doesn’t.

[5]Stack

TriggerMatching or nesting, or anything where you need the most recent thing.

The move

A Python list is a stack: append to push, pop() to pop from the end.

Template — Valid Parentheses (20)

python
def isValid(self, s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []

    for char in s:
        if char in pairs:
            if not stack or stack.pop() != pairs[char]:
                return False
        else:
            stack.append(char)

    return not stack

Three failure modes, all covered above: wrong type, a closer with nothing open (empty stack), and leftover openers — which is why the last line is return not stack rather than return True.

Monotonic stack

A variant where you keep the stack sorted, popping anything that breaks the order. It’s the answer to “next greater element” problems, and it recurs often enough to be worth recognising on sight.

[6]Greedy, running frontier

Trigger“Can you reach the end”, “minimum jumps to reach” — each position gives you a capability (how far you could go from here), not a value to compare against others.

The move

Not two pointers — one scanning index, plus one running value that summarises every position you’ve already passed: the farthest index reachable so far. You never revisit earlier positions or simulate an actual jump, because that running value already carries forward everything worth knowing about them. If the scan ever walks past that frontier, there was no way to have legally arrived there.

Template — Jump Game (55)

python
def canJump(self, nums):
    # farthest is the best index we know we can reach so far
    # if the scan pointer ever gets past farthest, we're stuck
    farthest = 0

    for i in range(len(nums)):
        if i > farthest:            # walked past the frontier - no jump got us here
            return False

        jump = i + nums[i]          # furthest this index could reach, if we chose to jump from it
        if jump > farthest:
            farthest = jump          # new frontier - carried forward, never recomputed

    return True                     # scan finished without ever outrunning the frontier
Watch forA zero in the middle of the array isn’t automatically a dead end — it only matters if nothing before it already pushed farthest past it. Don’t special-case zeros; the running max handles them for free.

Variant — minimum jumps instead of reachability

Jump Game II asks for the fewest jumps, not just whether it’s possible. Track the current jump’s boundary separately from the next jump’s frontier, and count a jump only when the scan runs out of room in the current one.

python
def jump(self, nums):
    jumps = 0
    current_end = 0      # farthest reachable using jumps taken so far
    farthest = 0          # farthest reachable if one more jump is taken

    for i in range(len(nums) - 1):     # never need to jump FROM the last index
        farthest = max(farthest, i + nums[i])

        if i == current_end:           # exhausted the current jump's range
            jumps += 1
            current_end = farthest      # commit to the best option seen during it

    return jumps

[7]Linked list operations

TriggerThe problem hands you a ListNode instead of an array — anything with a .next.

Before you write anything

You’re always given: class ListNode: def __init__(self, val=0, next=None): self.val, self.next = val, next. Four moves cover almost every problem — name which one you’re in before coding.

One — dummy head

When the head itself might get removed or replaced, point a fake node at it so every real node — including the first — gets handled by the same code path. No special case for “what if we’re deleting index 0.”

python
dummy = ListNode(next=head)   # dummy.next always points at the current true head
prev = dummy
# ... walk `prev` and delete/insert after it, same code whether or not head changes ...
return dummy.next              # not head - head may have been removed

Two — fast / slow runner

Two pointers into the same list, moving at different speeds. Fast moving twice as fast as slow means: when fast finishes, slow is at the midpoint. If the list has a cycle, fast eventually laps slow and they meet.

Three — reversal triple: prev, curr, next

Reversing links in place means you overwrite curr.next — so you must save where it pointed before you overwrite it, or the rest of the list is unreachable.

Four — two chains, then join

For splitting into groups while preserving order. Append to the tails of two new lists rather than moving nodes around inside the original — see below.

Template — Reverse Linked List (206)

python
def reverseList(self, head):
    prev = None
    curr = head

    while curr:
        next_node = curr.next   # save it - about to overwrite curr.next
        curr.next = prev        # reverse this link
        prev = curr              # advance both pointers
        curr = next_node

    return prev                 # prev ends on the old tail - the new head
Watch forReading curr.next after reversing it reads your own new value, not the original next node. Save next_node first, every time, no exceptions.

Template — fast / slow runner

python
def middleNode(self, head):        # 876 - find the middle
    slow = fast = head

    while fast and fast.next:      # fast needs 2 steps left, or stop
        slow = slow.next            # 1 step
        fast = fast.next.next       # 2 steps

    return slow                    # fast ran out first - slow is at the middle

def hasCycle(self, head):          # 141 - detect a cycle
    slow = fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:            # they met - only possible inside a loop
            return True

    return False                   # fast hit the end - no cycle
Watch forThe loop condition is fast and fast.next, not just fast — you dereference fast.next.next inside the loop, so fast.next must be checked first or you hit an AttributeError on a null.

Template — dummy head: Remove Nth From End (19)

python
def removeNthFromEnd(self, head, n):
    dummy = ListNode(next=head)
    fast = slow = dummy

    for _ in range(n):
        fast = fast.next            # push fast n nodes ahead of slow

    while fast.next:                # when fast hits the last node...
        fast = fast.next
        slow = slow.next            # ...slow sits right before the node to remove

    slow.next = slow.next.next      # skip over it
    return dummy.next

The n-node head start is what converts “nth from the end” — which needs the length — into a single pass with no length calculation.

Habits that catch the silent bugs

Linked-list bugs mostly don’t raise anything — they hang or quietly corrupt the list. Python won’t flag them, so the catching has to happen as you write.

Read the left side first: travelling or rewiring?

These look nearly identical and do completely different things. Travelling is the common case; you usually rewire once, at the end.

python
node = node.next     # bare name on the left  -> MOVING through the list
node.next = other    # .next on the left      -> EDITING the list structure

node.next = node     # points a node at itself: infinite loop + corrupted list

If there’s a .next on the left and you weren’t deliberately restructuring, it’s wrong.

Point at the line that ends the loop

For every while, name the line that moves you toward the exit condition, and check it actually changes the value. These are legal Python and fail silently:

python
size =+ 1       # parses as  size = +1  -> pinned at 1 forever
size += 1       # what you meant

i -= 0          # subtracts nothing -> infinite loop
i -= 1

A guard that moves the error is the wrong fix

A correct fix makes an error disappear. If adding a condition just relocates the crash to the next line, stop patching and go find why the value was bad in the first place.

Make the name match the value

dummy = head is not a dummy — it’s a second name for the head. Either build the real thing (dummy = ListNode(0, head)) or rename it to what it is (walker, counter). Names are how you track intent twenty lines later.

Trace the one-element case before submitting

Run [1] with n = 1 in your head. Empty and single-element inputs catch a disproportionate share of these bugs, because that’s exactly where “the node before this one” stops existing.

Build new chains, don’t rearrange the old one

Trigger“Partition”, “group these together”, “separate odds and evens” — preserving relative order.

The instinct is to walk the list and splice nodes toward the front. That fails, because moving a node needs three pointer updates, and you only ever hold two of them — the node that currently points at the one you’re moving is not in your hands. Leave it stale and you fork the list into a cycle.

python
# moving D to the front, having walked ... C -> D -> E ...
A.next = D      # A points at D
D.next = B      # D points at B
                # but C.next is STILL D  ->  A->D->B->C->D->B->C...  cycle

Instead: never insert into the middle. Walk once and append each node to the tail of one of two new chains, then join them. Appending needs only the tail you already hold, and visiting in order means each chain comes out in order for free.

Template — Partition List (86)

python
def partition(self, head, x):
    less_head = ListNode(0)      # dummy for the "< x" chain
    less_tail = less_head

    more_head = ListNode(0)      # dummy for the ">= x" chain
    more_tail = more_head

    node = head
    while node:
        next_node = node.next    # save it - about to overwrite node.next

        if node.val < x:
            less_tail.next = node    # append to the tail we already hold
            less_tail = node
        else:
            more_tail.next = node
            more_tail = node

        node.next = None         # cut it loose from the old list
        node = next_node

    less_tail.next = more_head.next   # join the two chains
    return less_head.next             # skip the dummy
Watch forThe second chain must be terminated — if the original tail landed in the < x chain, whatever more_tail.next still points at will drag the old list back in. Setting node.next = None as you detach each node handles this.

Losing the rest of the list

The single most common linked-list bug: overwriting .next before reading it.

python

Checking node.val on a null

python

Part two — search algorithms

Binary search — read this first

Every binary search bug is one of three things: a range that doesn’t shrink, a boundary that’s off by one, or the wrong template for the question. Settle these four decisions before you type, and the code is mechanical.

One — what is actually being searched?

Not always an array. Binary search needs a range and a yes/no question whose answer flips exactly once across it. Sortedness is just the most common way to get that property.

the search space
indices    0 .. len(nums)-1     # classic: find a value in a sorted array
answers    1 .. max(piles)      # "minimum speed such that..." - no array at all

The test: walk the range left to right and ask your yes/no question at each point. If the answers read no no no yes yes yes — one flip, never flipping back — binary search applies. If they read no yes no yes, it does not, no matter how sorted the input looks.

Two — hold the invariant

The one sentence that keeps you honest: “the answer, if it exists, is still inside [left, right].” That has to be true before the loop and after every single step. When you discard a half, ask: am I certain the answer isn’t in there? If you’re not certain, you’re discarding too much.

Three — pick the template from the question

There are two, and picking wrong is the most common source of off-by-ones. The question you’re answering tells you which.

python
# "is this exact value present?"   -> exact-match form
while left <= right:          # <=  so a 1-element range is still checked
    ...
    left  = mid + 1           # both sides EXCLUDE mid
    right = mid - 1
return -1                     # nothing left to check

# "smallest thing that works" / "first index where..." -> boundary form
while left < right:           # <   stop when they meet
    ...
    right = mid               # mid might BE the answer - keep it
    left  = mid + 1           # mid definitely isn't - drop it
return left                   # left == right == the boundary

The asymmetry is the whole point: right = mid - 1 says “mid is ruled out”; right = mid says “mid is still a candidate, I just want to know if something earlier also works.” Boundary problems never return from inside the loop — they narrow until one candidate remains.

Four — prove the range shrinks

The infinite loopmid = (left + right) // 2 rounds down, so when right == left + 1 you get mid == left. If a branch then does left = mid, nothing changed and it spins forever. Every branch must either move past mid or cut the range on the side that does move.

Trace it once

nums = [1,3,5,7,9,11], looking for 7 with the exact-match form:

trace
left=0 right=5  mid=2  nums[2]=5  < 7  -> left = 3
left=3 right=5  mid=4  nums[4]=9  > 7  -> right = 3
left=3 right=3  mid=3  nums[3]=7  == 7 -> return 3

# and for a value that isn't there, 6:
left=3 right=3  mid=3  nums[3]=7  > 6  -> right = 2
left=3 right=2                          -> left > right, exit, return -1

Note the third line: left == right == 3. That single-element range is exactly what <= exists to check, and using < there would skip the answer.

Where to start

  2. 35 Search Insert Position — same code, but now you return left instead of -1 when it’s missing. First taste of why left is meaningful at the end.

Binary search — the base template

TriggerSorted input and you need better than O(n).

The move

Halve the range every step. A million elements take about twenty steps. O(log n) time, O(1) space.

Template — Binary Search (704)

python
def search(self, nums, target):
    left, right = 0, len(nums) - 1

    while left <= right:              # <= : a single remaining element still counts
        mid = (left + right) // 2     # midpoint of the current range

        if nums[mid] == target:
            return mid                 # found it
        elif nums[mid] < target:
            left = mid + 1             # target is to the right - drop the left half
        else:
            right = mid - 1            # target is to the left - drop the right half

    return -1                          # range shrank to nothing without a match
The two bugs that cause most failuresleft <= right, not < — with < you miss the case where one element remains. And mid + 1 / mid - 1, not mid — using mid stops the range shrinking and loops forever.

Variant — search for a boundary

TriggerDuplicates exist and you want the first or last match.

The move

Don’t return on equality — record the hit and keep narrowing.

Template — Find First and Last Position (34)

python
def findFirst(nums, target):
    left, right = 0, len(nums) - 1
    result = -1                  # best match found so far, or -1

    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            result = mid          # record the hit...
            right = mid - 1       # ...but don't stop - keep searching left for an earlier one
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return result

For the last occurrence, flip that one line to left = mid + 1.

Variant — rotated input

TriggerA sorted array that’s been rotated.

The move

A rotated sorted array still has one sorted half at every step. Work out which half is sorted, then decide whether the target lies inside it.

Template — Search in Rotated Sorted Array (33)

python
def search(self, nums, target):
    left, right = 0, len(nums) - 1

    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid

        if nums[left] <= nums[mid]:              # left half [left..mid] is sorted
            if nums[left] <= target < nums[mid]:  # target falls inside that sorted half
                right = mid - 1
            else:                                  # target must be in the other half
                left = mid + 1
        else:                                    # otherwise right half [mid..right] is sorted
            if nums[mid] < target <= nums[right]:  # target falls inside that sorted half
                left = mid + 1
            else:                                  # target must be in the other half
                right = mid - 1

    return -1

Variant — search on the answer

Trigger“Minimum speed”, “smallest capacity”, “least time such that…” — no array to search, but a range of possible answers that’s monotonic. If an answer works, every larger one works too.

The move

Binary search the answer range, using a feasibility check as the comparison.

Template — Koko Eating Bananas (875)

python
def minEatingSpeed(self, piles, h):
    def hours(speed):                              # hours needed to clear every pile at this speed
        return sum((p + speed - 1) // speed for p in piles)

    left, right = 1, max(piles)   # slowest possible / fastest-ever-needed speed

    while left < right:
        mid = (left + right) // 2
        if hours(mid) <= h:
            right = mid          # this speed works - try slower
        else:
            left = mid + 1       # too slow to finish in time - go faster

    return left                  # left == right: the smallest speed that still works
Different templateThis one uses left < right and returns left — the convergence form, used when you’re finding a boundary rather than an exact match. (p + speed - 1) // speed is integer division rounding up.

BFS — breadth first search

TriggerShortest path in an unweighted graph, level-by-level traversal, “minimum number of steps”.

The move

Uses a queue. Explores everything one step away, then everything two steps away — so the first time you reach a target, you got there by the shortest route.

Level order: root → both children → all four grandchildren. One full row finishes before the next starts.

Template — grid traversal

python
from collections import deque

def bfs(grid, start):
    q = deque([start])     # cells waiting to be explored, in discovery order
    seen = {start}         # cells already enqueued, so we don't add them twice

    while q:
        r, c = q.popleft()               # oldest-enqueued cell first - what makes it BFS

        for dr, dc in ((0,1), (0,-1), (1,0), (-1,0)):   # the four neighbours
            nr, nc = r + dr, c + dc
            if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]) \
                    and (nr, nc) not in seen and grid[nr][nc] == "1":
                seen.add((nr, nc))       # mark seen at enqueue time, not dequeue time
                q.append((nr, nc))
Watch forUse deque and popleft(), not a list and pop(0) — the latter is O(n) per removal. And mark cells as seen when you enqueue them, not when you dequeue, or you’ll add duplicates.

Variant — level order on a tree

Process the queue one full level at a time.

python
def levelOrder(self, root):
    if not root:
        return []

    result = []
    q = deque([root])

    while q:
        level = []
        for _ in range(len(q)):          # snapshot this level's size before adding the next one
            node = q.popleft()
            level.append(node.val)
            if node.left:
                q.append(node.left)       # children go on the queue - visited next level
            if node.right:
                q.append(node.right)
        result.append(level)              # one finished level

    return result

for _ in range(len(q)) captures the level’s size before you start adding the next level. That’s the whole trick.

DFS — depth first search

TriggerExplore every path, count connected regions, anything on a tree.

The move

Uses recursion — the call stack is your stack. Goes as deep as possible, then backs up.

Visit order: 1 → 2 → 3, dead end, back to 2, → 4, back to 1, → 5 → 6, back to 5, → 7.

Template — grid flood fill

python
def dfs(grid, r, c):
    if r < 0 or r >= len(grid) or c < 0 or c >= len(grid[0]):
        return                        # base case: fell off the grid
    if grid[r][c] != "1":
        return                        # base case: water, or already visited

    grid[r][c] = "0"                 # mark visited before recursing, or this loops forever

    dfs(grid, r + 1, c)               # go deep down each neighbour in turn...
    dfs(grid, r - 1, c)               # ...each call fully finishes (backtracks)
    dfs(grid, r, c + 1)               # ...before the next one starts
    dfs(grid, r, c - 1)

Every DFS opens with base cases: out of bounds, already visited, or wrong value. Miss one and you recurse forever.

Variant — on a tree

The base case is just if not node: return.

python
def maxDepth(self, root):
    if not root:
        return 0                                              # base case: past a leaf
    return 1 + max(self.maxDepth(root.left), self.maxDepth(root.right))
    #      ^ this node          ^ deepest of the two subtrees, found on the way back up

The recursive calls return values that get combined on the way back up — the same build-on-the-unwind behaviour as constructing a BST from a sorted array (108).

BFS or DFS?Shortest path calls for BFS. Anything else on a tree or grid, DFS is usually shorter to write.

Tree recursion — one shape, many problems

TriggerAnything on a binary tree that isn’t level-order. Trees and BSTs carry a lot of weight at Google — see the plan.

The shape

Almost every tree problem is this skeleton. Only two lines ever change — the base case and the combine step. Write the skeleton first, then fill in those two.

python
def solve(node):
    if not node:                  # BASE CASE - what does an empty tree answer?
        return identity

    left = solve(node.left)       # trust the recursion: both subtrees come back solved
    right = solve(node.right)

    return combine(left, right, node.val)   # COMBINE on the way back up

The hard part is psychological, not technical: you have to trust that solve(node.left) already works and just use its answer. Don’t trace the whole recursion in your head — decide what the two subtree answers mean, and how to merge them with this node.

Template — Maximum Depth (104)

python
def maxDepth(self, root):
    if not root:
        return 0                          # an empty tree has depth 0

    left_depth = self.maxDepth(root.left)
    right_depth = self.maxDepth(root.right)

    return 1 + max(left_depth, right_depth)   # this node, plus the deeper side

Naming the two results rather than nesting the calls inline is worth the extra lines — it makes the “solve both, then combine” shape visible, and it’s where you’d put a print statement when debugging.

Two directions of information

This is the distinction that decides how you write a tree problem. Ask it before coding.

Bottom-up — answers flow back up

The default, and everything above. Each node needs its children’s answers. No extra parameters.

Top-down — constraints flow down

When a node’s validity depends on its ancestors, you can’t learn that from its children — you must carry it down as arguments. Validate BST is the classic: checking left.val < node.val < right.val locally is wrong, because every node in the left subtree must be below the ancestor, not just the immediate parent.

python
def isValidBST(self, root):
    def check(node, low, high):        # the allowed range, narrowed on the way down
        if not node:
            return True                 # empty tree is a valid BST

        if not (low < node.val < high):
            return False                # violates a bound set by some ancestor

        return (check(node.left,  low, node.val) and    # left subtree: cap at this node
                check(node.right, node.val, high))      # right subtree: floor at this node

    return check(root, float("-inf"), float("inf"))
Watch forIf a problem’s answer depends on the path from the root (running sum, allowed range, depth so far), it’s top-down — add a parameter. If it depends on what’s below (height, count, subtree sums), it’s bottom-up — return a value. Getting this backwards is why Validate BST catches people.

Template — Lowest Common Ancestor (236)

Worth memorising; the code is shorter than the explanation.

python
def lowestCommonAncestor(self, root, p, q):
    if not root or root is p or root is q:
        return root                # found one of them, or ran off the tree

    left = self.lowestCommonAncestor(root.left, p, q)
    right = self.lowestCommonAncestor(root.right, p, q)

    if left and right:
        return root                # p and q found on opposite sides - this IS the split point
    return left or right           # both on one side - pass up whichever found something

Each call returns “what did I find below me”. Finding something on both sides can only happen at the node where the two paths diverge, which is the answer by definition.

When one return value isn’t enough

Some problems ask for one thing but need another to compute it. Diameter (543) asks for the longest path anywhere, but recursion can only usefully return height. Return the height, and record the answer in an outer variable as you go.

python
def diameterOfBinaryTree(self, root):
    best = 0

    def height(node):
        nonlocal best
        if not node:
            return 0

        left = height(node.left)
        right = height(node.right)

        best = max(best, left + right)   # path THROUGH this node - the answer candidate
        return 1 + max(left, right)      # what the PARENT needs - the height

    height(root)
    return best

nonlocal lets the inner function write to best in the enclosing scope. Without it, best = ... would create a fresh local each call and the updates would vanish. Same structure solves Binary Tree Maximum Path Sum (124).

Mistakes to check for

Forgetting the empty-tree base case. Every tree function starts with if not node:. Miss it and you get AttributeError: 'NoneType' object has no attribute 'val'.

Returning the wrong thing for the parent. In the diameter pattern, returning best instead of the height breaks every ancestor’s calculation. The return value is a contract with the parent; the answer is separate.

Using == instead of is for node identity in LCA — you’re asking “is this the same node”, not “same value”.

Part three — when it breaks

Stuck? Run this checklist

The mistakes that actually keep costing you time, with the error each one produces. Read the traceback first — the exception name usually points straight at which of these it is.

Fastest triageAttributeError: 'NoneType' has no attribute… → you dereferenced before guarding. IndexError: list index out of range → your loop condition let you run past the end. Right answer but wrong array → you rebound instead of mutating. Infinite loop → a pointer isn’t moving.

Notation — syntax that bites

or vs and in a loop condition

This one has cost you twice. or keeps the loop alive if either side is still true — so a condition meant to stop you never does, and you run off the end.

python
while right != 0 or right < len(nums):   # WRONG - right != 0 stays true forever
                                          # -> IndexError
while head or head not in seen:           # WRONG - None not in seen is True
                                          # -> AttributeError on head.next

# a stopping condition almost always wants ONE clear test, or `and`
while right < len(nums):
while head:

Sanity check: say the condition out loud as “keep going while ___”. If you can finish that sentence with a single fact, you don’t need a second clause at all.

Guard before you dereference

Python evaluates left to right and short-circuits — so the existence check has to come first, in the same expression.

python
while head.next != None:      # WRONG - crashes when head itself is None
if node.val == x:             # WRONG - same problem

while head:                   # RIGHT - "while head is not None"
if node and node.val == x:    # RIGHT - `and` stops before touching .val
while fast and fast.next:     # RIGHT - you use fast.next.next inside, so check both

is vs == for nodes

ListNode defines no __eq__, so == already falls back to identity — same object, not same value. Both work; is says what you mean.

python
if slow is fast:      # "the same node object" - preferred for pointers
if slow == fast:      # identical behaviour here, but reads like a value check

Declaring an empty thing

python

seen = set()           # RIGHT - empty set

head = []              # WRONG - a Python list is not a linked list
head = None            # RIGHT - an empty linked list is just a null head
node = ListNode()      # a single node: val=0, next=None

Concepts — the thinking mistakes

Identity vs value when tracking “seen”

Storing .val answers “have I seen this number”, which is not the question. [1,1,1] with no cycle would false-positive immediately.

python
seen.add(head.val)     # WRONG - duplicate values look like a revisit
seen.add(head)         # RIGHT - nodes hash by identity, so this means "this exact node"

Let the data structure do the lookup

If you’re looping over a set to find something, you’ve turned an O(1) lookup back into O(n) and thrown away the only reason to use a set.

python
for node in seen:          # WRONG - O(n) scan per iteration -> O(n^2) total
    if node is head:
        return True

if head in seen:           # RIGHT - O(1)
    return True

Every pointer in the loop has to move

An infinite loop or a “nothing changed” result usually means one pointer was set once and never advanced — or advanced the wrong direction.

python
left = 0
while ...:
    nums[left] = nums[right]
    right += 1              # WRONG - left never moves, you rewrite nums[0] forever

# converging pointers move TOWARD each other:
while left < right:
    left += 1
    right -= 1              # not += 1 - that walks them apart, past the ends

Rebinding vs mutating

Assigning to the parameter name swaps out your local label. The caller still sees the original object.

python
nums = result       # WRONG - rebinds a local name, caller sees nothing
nums[:] = result    # RIGHT - overwrites the contents in place
nums[:k] = result   # RIGHT - for "return k" problems

Linked lists: relink .next, don’t overwrite .val

Merging and reordering means rewiring existing nodes, not copying values into one node. Writing head.val = … in a loop leaves you with a single node at the end.

python
head.val = list1.val       # WRONG - one node, overwritten each pass
current.next = list1       # RIGHT - splice the actual node into the chain
current = current.next     # ...and advance the builder pointer

Return dummy.next, not dummy

The dummy is a placeholder whose .val is meaningless. The real list starts one node later.

“Reached the end” vs “past the end”

Landing exactly on the last index normally counts as success. Requiring an overshoot is an off-by-one.

python
if reach > len(nums):        # WRONG - demands overshooting the whole array
if reach >= len(nums) - 1:   # RIGHT - reaching the last index is enough
Before you submitDoes every pointer move on every path? Is each .next / index guarded by an existence check first? Are you mutating the input the problem asked you to mutate? Did you handle the empty input and the single-element input?

String mutation

Strings are immutable. You cannot change one in place.

python

Every string method returns a new string and leaves the original alone. This is the opposite of list methods like sort() and append(), which mutate and return None. To “modify” a string, convert to a list, change it, join it back.

python
